# 按需资源下载的 Hash 记录

2026-11-21。本轮调整资源页和 `RuntimeService` 的单个下载包处理，覆盖原始文件、压缩包和可执行安装包。多文件模型快照继续使用已有的固定版本策略。

## 行为

1. 当前平台有下载包时，缺少预设 SHA-256 不再禁用下载按钮，也不再被后端提前拒绝。
2. 下载完成后计算实际 SHA-256。有上游预设值时优先比对；没有预设值时，尝试读取现有安装账本中同资源 ID、同版本、同下载来源的 Hash。
3. 已知 Hash 不匹配时，终止安装、清理下载暂存，并保留原安装及原记录。账本损坏会明确报错，不会悄悄重建基准。
4. 没有可比对的 Hash 时，首次下载建立本地记录。安装成功后，将实际 SHA-256、版本、实际供给文件的来源 URL 和安装位置写入已有的 `install-ledger.json`，不新增账本或修改其 schema。
5. 来源切换、版本变化会建立新的记录。已存在的上游预设 Hash 优先于本地记录。镜像下载记录实际镜像 URL，后续与当前配置的主地址及镜像地址匹配。
6. 记录写入失败会返回错误。卸载继续沿用原有账本生命周期，同步移除此资源记录；之后首次下载会重新建立基准。

首次计算所得 Hash 只说明本次下载内容的摘要，并不证明文件来自官方，也不回写成上游预设值。`checksum_pinned` 保留原契约作为注册表元数据，不把首次记录伪装为官方校验。

这是基于现有安装账本的本地设计：复用现有持久化、文件锁和原子写入，避免新增与安装状态竞争的另一套记录。

## 验证

- 前端新增 4 个可用性回归用例：缺 Hash 可下载、已有 Hash 可下载、平台不支持仍不可用、已安装资源可用。修改前缺 Hash 用例失败，修改后通过。
- 新增 8 个 Rust 回归用例，全部通过：首次记录、重启后复用和拒绝变化、内容不变、版本或地址变化、上游值优先、解压失败不记录、损坏账本拒绝重建、镜像来源与 Hash 记录。
- 独立 Rust 源码测试工程直接引用生产 `runtime_service.rs`、安装账本、原子写入及文件锁，使用实际 `deepagent-core` 和 `deepagent-workspace`。仅适配未使用的 `UserPaths` 构造入口，并从生产文件提取 DTO。共 47 项中 46 项通过；`project_runtime_wins_over_managed_fallback` 在当前机器失败，使用修改前 HEAD 源码单独运行也复现同一 Local/Managed 断言失败。
- 完整 `pnpm build` 通过，包含专项回归、现有构建检查、TypeScript 和 Vite 产物生成。
- 浏览器加载真实资源页组件，使用模拟 Tauri 数据：Pandoc、PDFium、LibreOffice 的缺 Hash 下载按钮可点击，平台不支持的条目仍禁用；点击 Pandoc 后确认调用安装入口并显示已安装。该验证未安装外部软件。
- 修改文件的 Rust 格式检查、Git diff 空白检查通过。所有构建、测试缓存及证据均在 D 盘。

## 既有下载源限制

本轮没有修改资源版本、包格式或下载地址。Pandoc、PDFium 的 GitHub 下载地址 HEAD 请求超时，未证实可用；现有 LibreOffice portable 24.8 ZIP 地址 HEAD 返回 404。取消缺 Hash 限制不解决下载源本身失效，LibreOffice 还需要单独修复来源及安装方式。
