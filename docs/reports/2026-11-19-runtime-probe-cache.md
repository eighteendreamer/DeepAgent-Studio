## 用户决定与范围

首次探测 Node、Python、Java 后将结果写入磁盘，跨软件重启复用；安装、卸载或路径变化时更新。本项处理运行环境解析，不变更供应商、思考档位、协议、权限、沙箱或远程连接。

此前秒级准备耗时的口径及样本保留在 [请求准备耗时报告](2026-11-19-request-preparation-latency.md)。首次登录和基础设置不计入请求准备；运行环境探测只是其中一项，不能把其优化等同于消除全部准备耗时。

## 已核对的调用边界

`RuntimeService::build_process_environment` 每次按项目、PATH、managed fallback 优先级解析三个 SDK，`resolve_runtime` 会启动候选程序执行 `--version`。桌面启动及每轮 Hook 装配均调用这个入口。启动还会把解析后的环境写回宿主进程，因此以完整 PATH 文本缓存整份环境容易因自身追加 PATH 而失效。

本地设计：复用候选可执行文件的版本记录，仍按当前项目、PATH、托管目录选择候选，并逐次校验版本约束。候选缺失、新增、顺序改变或文件身份变化时，解析能重新选择或探测。记录不包含审批、取消、权限、会话或模型运行对象，也不替代实际执行时的沙箱验证。

持久化复用既有 `atomic_file::write_file_atomically`，并发写入使用既有文件锁原语，不新增依赖、数据库或对外 command。有数据根时写入 `<data-root>/cache/runtime-probes/`；没有数据根的宿主写入当前运行资源根的 `.probe-cache/`。文件名使用可执行文件规范路径的摘要，每个文件独立存一条版本记录，避免不同宿主更新不同运行时而互相覆盖。

每次读取检查规范路径、文件大小、修改时间、创建时间及只读属性；Unix 额外检查设备、inode、ctime 和 mode。检查并不启动进程或读取整份二进制。新项目候选和 PATH 顺序仍由现有解析器决定；记录只缓存版本，不缓存“满足版本约束”的判断。文件在探测期间变化会丢弃本次结果。记录损坏或不可写会告警并使用真实探测结果；不可写情况下保留进程内复用。此记录属于发现提示，不是二进制防篡改校验或执行授权。

## Harness 生命周期参考

- DeepSeek Harness：`借鉴/deepseek-harness/packages/core/agent-loop/src/agent.ts` 的 `ReactLoopAgent` 属于会话生命周期；构造时创建 dispatcher、scope、模型选择与上下文投影。`runtime-context.ts` 的投影恢复一次后跟随会话事件。它并非在每次请求中无条件重新创建所有对象。
- 天枢：`借鉴/Tianshu-harness/src/prompt/engine.ts` 区分稳定块、每条用户消息的 fresh 块和历史冻结快照；同一用户消息的工具续写复用 fresh 块。`src/bootstrap.ts` 在会话或工作目录切换时重建绑定身份的对象，避免沿用旧会话的持久化和事件通道。
- 本项目：插件准备已有 host 级快照与失效机制（`plugin_preparation.rs`）。`run_assembler.rs` 的工具和 Hook 仍绑定本轮 sink、审批 gate、权限、取消 token、模型快照及运行记录，不能直接全局缓存整个注册表。

下一步的复用边界应是稳定的数据与声明：工具 schema、解析后的配置和指令、版本记录。会话历史、当前 Git 状态、权限与信任撤回、附件、审批和取消继续从对应的可信来源取得。先细分计时，再为有实测成本的数据设计失效测试，避免另建一条运行链。
