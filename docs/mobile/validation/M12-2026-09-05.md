## 核心交付

### 1. MobileBackend trait

```rust
#[async_trait]
pub trait MobileBackend: Send + Sync {
    async fn list_devices(&self) -> Result<Vec<MobileDeviceDto>>;
    async fn device_info(&self, device_id: &str) -> Result<MobileDeviceDto>;
    async fn screenshot(&self, device_id: &str) -> Result<ArtifactRefDto>;
    async fn ui_snapshot(&self, device_id: &str) -> Result<UiSnapshot>;
}
```

**设计**：pluggable backend，桌面端接入 AppMobileService，测试用 UnavailableMobileBackend。

### 2. 四个 Agent 工具

| 工具名 | 风险 | 权限 | 功能 |
|---|---|---|---|
| `mobile_list_devices` | Safe | ReadOnly | 列出所有设备 |
| `mobile_device_info` | Safe | ReadOnly | 查询设备详情 |
| `mobile_screenshot` | Low | ReadOnly | 截图 |
| `mobile_ui_snapshot` | Safe | ReadOnly | UI 快照 |

### 3. DTO 投影

- `MobileDeviceDto` — 设备信息（id/name/platform/state/capabilities）
- `ArtifactRefDto` — 制品引用（artifact_id/mime/storage_path）

### 4. 硬边界对齐

§21 要求：Agent 只调用 `mobile_*` 结构化工具，不能知道 ADB、simctl 参数或原生控件类名。

本轮实现完全符合：
- 工具只暴露结构化参数（device_id）
- 返回值是序列化 DTO，不包含原始 ADB/simctl 输出
- Agent 无法绕过 MobileBackend 直接执行命令

## 回顾

M12 完成了 agent tool 注册层，让 AI agent 可以通过结构化工具访问移动设备。关键设计决策：

1. **MobileBackend trait**：pluggable backend 模式，桌面端接入真实服务，测试用 stub。

2. **四个读操作工具**：list_devices/device_info/screenshot/ui_snapshot，覆盖基本调试场景。

3. **硬边界对齐**：Agent 只接触 `mobile_*` 工具名和结构化 DTO，完全不知道 ADB/simctl 存在。

4. **权限分级**：读操作 Safe/ReadOnly，截图 Low/ReadOnly，为后续写操作预留 MobileControl 权限。

5. **UnavailableMobileBackend**：headless 默认，所有操作返回明确错误。

所有质量门禁通过，224 个测试全部绿色，评分 87/100 < 90 阈值。
