## 核心交付

### 1. RemoteMacManager

管理多个 Remote Mac 连接的编排层：

```rust
pub struct RemoteMacManager {
    inner: Arc<Mutex<ManagerInner>>,
}
```

**核心方法**：
- `add_config(config)` — 注册配置，不连接
- `remove_config(config_id)` — 移除配置，断开连接
- `connect(config_id)` — 通过 TransportFactory 创建 transport 并连接
- `disconnect(config_id)` — 断开连接，取消所有请求
- `send_request(config_id, request)` — 路由请求到正确的 session
- `health(config_id)` — 单个 Mac 健康探测
- `aggregated_health()` — 聚合所有 Mac 的健康状态
- `discover_remote_devices(config_id)` — 发现远程设备并注册到 DeviceRegistry
- `list_configs()` — 列出所有配置 ID
- `state(config_id)` — 查询连接状态

### 2. TransportFactory Trait

```rust
pub trait TransportFactory: Send + Sync {
    fn create(&self, config: &RemoteMacConfig) -> Box<dyn RemoteTransport>;
}
```

工厂模式隔离了 transport 创建细节，测试可注入 FakeRemoteTransport。

### 3. 远程设备发现与注册

`discover_remote_devices` 发送 ListDevices 请求到远程 agent，解析响应中的设备描述符，为每个设备设置 `DeviceConnection::Remote { host_id: config_id }`，并通过 `DeviceRegistry::upsert` 注册。

设备 ID 格式：`remote-{config_id}-{device_id}`，确保不与本地设备冲突。

### 4. 聚合健康状态

```rust
pub struct AggregatedHealth {
    pub total_macs: usize,
    pub connected_macs: usize,
    pub healthy_macs: usize,
    pub per_mac: Vec<MacHealthEntry>,
}
```

遍历所有配置，查询每个 session 的状态和健康，统计连接数和healthy数。

### 5. FakeRemoteTransport::with_initial_state

同步构造器，允许在 async 上下文中创建预配置的 fake transport，避免 `blocking_lock()` 在 tokio runtime 中 panic。

### 6. RemoteMacManagerError

三种错误变体：
- `ConfigAlreadyExists` — 重复注册
- `ConfigNotFound` — 配置不存在
- `Transport` — 底层 transport 错误

## 回顾

M8 完成了 Remote Mac 的编排层，将 M7 的协议/transport 抽象提升为可管理多连接的服务。关键设计决策：

1. **TransportFactory 模式**：隔离 transport 创建，测试可注入 fake，未来可切换 SSH 实现。

2. **远程设备 ID 命名**：`remote-{config_id}-{device_id}` 确保全局唯一，不与本地设备冲突。

3. **DeviceRegistry 集成**：远程设备通过 `DeviceConnection::Remote { host_id }` 标识，复用现有设备管理基础设施。

4. **同步构造器**：`FakeRemoteTransport::with_initial_state` 避免在 async 上下文中使用 `blocking_lock()`。

5. **聚合健康**：提供全局视图，便于 UI 展示和决策。
