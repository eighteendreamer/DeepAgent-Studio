## 关键设计决策

### Artifact 协议类型

- **ArtifactRecord**：完整元数据（artifact_id、device_id、kind、mime、size_bytes、sha256、storage_path、lifecycle、created_at_ms、expires_at_ms）
- **ArtifactKind**：6 种已知类型（Screenshot/ScreenRecording/LogDump/UiSnapshot/NetworkCapture/Other）
- **ArtifactLifecycle**：3 种状态（Active/Expired/Purged）
- **MAX_ARTIFACT_SIZE**：256MB 硬限制，对齐 §28 "大对象必须限长"

### 查询与清理

- **ArtifactQuery**：支持 device_id、kind、lifecycle、since_ms、before_ms 过滤
- **ArtifactListRequest**：query + limit 分页
- **ArtifactPurgeRequest**：可选 device_id 范围 + dry_run 模式
- **ArtifactPurgeResult**：purged_count + purged_bytes 统计

### ArtifactStore 设计

- **内存存储**：`HashMap<String, ArtifactRecord>` + `Arc<Mutex<>>` 线程安全
- **单调 ID**：`art-{N}` 格式，自增序号
- **RegisterArtifactRequest**：请求 struct 避免参数过多（clippy too_many_arguments）
- **TTL 支持**：`ttl_ms` 可选，到期自动视为过期
- **dry_run**：purge 支持 dry_run 模式，不实际删除
- **clear_device**：设备断开时一次性清理该设备所有 artifact
- **to_ref**：转换为 `ArtifactRef` 用于事件发射，不暴露内部存储路径

### 设计对齐

- §28 "大对象必须限长、可取消、可过期清理" → MAX_ARTIFACT_SIZE + TTL + purge_expired
- §28 "只能写入应用数据目录或允许的 workspace 目录" → storage_path 由调用方提供，store 只跟踪元数据
- §28 "事件只保存 artifact_id、mime、size、hash、来源、生命周期和权限级别" → ArtifactRecord 包含全部字段，to_ref() 投影为事件安全引用
