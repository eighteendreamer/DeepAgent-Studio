# DeepAgent Studio 视频生成与本地编辑集成工程方案

> 方案版本：v3.0（云端生成 + 本地编辑并存）
> 状态：实施中（云端生成、artifact 流和 video-edit 基础链路已接入）
> 目标：保留画布视频节点的云端 API 生成能力，并新增可持久化的本地视频编辑节点。
> 核心原则：生成任务归模型网关；编辑工程归画布节点；所有媒体文件复用 artifact 存储。

---

## 1. 目标与关键决策

### 1.1 目标

本方案完整覆盖以下链路：

1. 用户配置视频生成节点，通过已配置的视频模型供应商调用云端 API。
2. 系统跟踪异步任务、进度、取消和续跑，并把完成视频保存到本地 artifact 库。
3. 用户把生成结果连接到独立的视频编辑节点，在本地时间线上继续剪辑。
4. 视频编辑节点保存可恢复的编辑工程，导出结果作为新的 artifact，供预览和下游节点使用。
5. 原始生成视频和本地导入视频均保留，不被编辑结果覆盖。

### 1.2 关键决策

- 保留现有 **video-gen** 云端生成链路；不删除 MediaJob、供应商配置、任务 ID、进度、续跑或取消逻辑。
- 本地编辑使用独立的 **video-edit** 节点；不把生成节点改成本地编辑节点。
- 编辑器按 ArtCraft **video-editor** 的 ProjectStorage、MediaSource、ExportSink 适配边界集成；经用户明确授权后允许直接借鉴其组件实现，生产打包仍需单独验证依赖和许可证。
- 编辑节点接受上游视频 artifact，也允许用户从磁盘导入本地视频。
- 编辑项目必须跨画布关闭和桌面重启恢复；编辑导出创建新 artifact，原片保持不变。
- 继续使用现有 **artifact://<id>** 作为节点中媒体资产的持久引用；不引入 **asset://** 或第二套媒体存储。
- 大文件通过文件流式读写 artifact 库，避免 base64 和整文件数组拷贝；不沿用当前 64 MiB 视频硬限制。
- **VideoEdit**、**VideoExtend** 和 **video-stitch** 只有在真实执行链路接通并通过测试后才宣称可用。

### 1.3 范围

本方案包括：

- 云端文生视频、图片参考生视频链路的现状核对和可用能力补齐。
- 本地编辑节点、编辑器适配、编辑工程持久化和导出。
- 视频媒体大文件的 artifact 导入、生成下载和导出写入。
- 旧画布兼容、测试、验收、灰度和回滚。

本方案不包括：

- 用本地模型替代云端视频生成。
- 未验证供应商支持就开放首尾帧、视频编辑、视频延长、音频驱动等模型操作。
- 把视频编辑器变成独立的第二套项目、资产或执行存储系统。
- 在没有授权时把 ArtCraft 代码打包到 DeepAgent Studio。

## 2. 当前实现与差距

### 2.1 云端视频生成

当前 **video-gen** 使用画布模型网关提交异步任务，并轮询供应商状态。运行时能够报告排队/运行阶段、检查取消标志，并保留任务 ID 供重跑时继续轮询。供应商返回的视频链接会被及时下载到 artifact 库，节点持久化 **artifact://** 引用，避免把短时签名 URL 放入画布。

当前运行时实际接通的是 **VideoGenerate**。请求能够包含提示词、可选图片参考、分辨率提示、模型引用、任务续跑 ID、取消标志和进度回调。

### 2.2 已知生成链路缺口

- 前端 **videoDuration** 有配置控件，但当前 **CanvasVideoRequest** 和网关供应商请求没有传递该值；界面显示并不代表服务端已支持。
- 当前图生视频请求仅有一个图片参考位。首尾帧、多参考图、视频输入编辑、视频延长等不能仅靠提示词或节点枚举宣称已支持。
- 节点契约列出了 **VideoEdit** 和 **VideoExtend**，但运行时拒绝除 **video_generate** 之外的操作。
- 视频生成结果使用现有 artifact 库，但 **CanvasArtifactService** 当前限制单个 artifact 为 64 MiB；大视频可能在下载完成后写库失败。
- 本地已有 **video-stitch** 节点契约和界面，但运行时明确返回“没有执行器”。不得把它描述为已完成的拼接功能。

### 2.3 本地视频编辑器参考

**借鉴/artcraft** 中存在独立的 React 视频编辑器组件、媒体源/工程存储/导出适配器接口，并提供 MP4、WebM 导出选项。其桌面宿主通过初始化编辑器实例并设置活动工程来启动，不是只传一个 **projectId** 属性就能自动恢复工程。

当前 ArtCraft 许可证文件标为 WIP，声明限制商业销售及开发竞争产品。因此它目前只能作为技术参考；正式依赖或打包必须先取得适用于本产品的书面授权。Tauri WebView 中的 GPU、WASM、解码器和编码器行为也必须单独验证。

## 3. 目标架构与数据流

### 3.1 完整数据流

~~~text
video-gen 节点
    ↓ 提交/续跑云端异步任务
CanvasModelGateway
    ↓ 轮询进度、检查取消
供应商 API
    ↓ 完成后下载视频
文件流 → 临时文件 → ArtifactStore 索引
    ↓ artifact:// URI
video-edit 节点
    ├─ 从上游读取 artifact:// 视频
    ├─ 或导入本地文件为 artifact:// 视频
    ├─ 保存编辑工程并恢复时间线
    └─ 导出 → 新 artifact:// 视频
                         ↓
                  下游节点 / 预览
~~~

生成器和编辑器之间仅通过 artifact URI 传递媒体；签名 URL、绝对路径、blob URL、视频字节和时间线大对象不写入画布图 JSON 或 run event。

### 3.2 职责边界

| 层 | 职责 |
|---|---|
| CanvasModelGateway | 解析模型、构造供应商请求、提交/轮询/取消云端视频任务、下载结果并存入 artifact 库 |
| Workflow Runtime | 执行 video-gen；为已导出的编辑节点验证输入和导出状态并投影 artifact 输出 |
| Artifact Service / ArtifactStore | 统一管理视频字节、媒体类型、校验信息和稳定 URI |
| Canvas UI | 配置生成参数、显示任务状态、打开编辑器、管理编辑草稿和导出结果 |
| Video Editor Adapter | 将 artifact/local file/project storage/toast/export 对接到编辑器接口 |
| Editor Project Storage | 按稳定工程 ID 持久化可恢复时间线；不是媒体字节的第二存储 |

### 3.3 生成和编辑的完成语义

- 云端生成任务成功且视频已进入 artifact 库后，**video-gen** 才能进入完成状态。
- **video-edit** 是交互式作者节点。时间线编辑发生在编辑器 UI；节点只有在成功导出后才有可供下游使用的输出。
- 编辑节点缺少输入视频、尚无成功导出或输入已经变化时，运行工作流必须返回明确的节点校验错误，不能假装输出了媒体。
- 编辑输出是新的 artifact；编辑失败或取消时保留上一次有效导出和原始输入，但将状态标记为失败/待重新导出，避免错误覆盖源资产。

## 4. 节点设计与兼容数据

### 4.1 video-gen 云端生成节点

保留现有节点类型、模型设置、提示词、节点状态、任务进度和任务 ID。契约首期只声明已接通的 **VideoGenerate**；旧数据中存在的 VideoEdit/VideoExtend 值仍可反序列化，但执行时明确报 UnsupportedCapability。首批可用输入严格匹配网关已经接通的能力：

- 文生视频：提示词必填，无图片参考。
- 图片参考生视频：提示词和一张图片参考；图片引用必须可被 artifact 库解析或属于供应商明确支持的远程 URL。

首期不显示 operation 选择器：无图片输入时走文生视频；有且仅有一张图片参考时走图片参考生视频；两者在网关中仍是已接通的 **VideoGenerate**。首期不允许用户把 video 输入、首尾帧或延长操作选成可执行模式。

模型专属参数遵循网关能力：只有当前模型/供应商适配器能传递且已验证的参数才显示。**videoDuration** 在真实供应商参数映射和回归测试完成前从首期表单隐藏；完成后仅对确认支持该参数的模型显示。禁止继续显示可编辑但不生效的时长值。

### 4.2 新增 video-edit 本地编辑节点

节点契约使用本地执行器、专用的 **VideoTimelineEdit** operation、Video/VideoList 输入和 VideoArtifact 输出。新增 operation 只描述本地交互式时间线编辑，不注册到 CanvasModelGateway 的供应商能力或请求路由。编辑操作只打开本地时间线，不调用云端模型。运行工作流时，runtime 只验证其已导出的 artifact 与输入摘要，并把有效的 VideoArtifact 输出给下游，不在后台启动编辑器 UI。

编辑节点使用稳定节点 ID 绑定编辑工程，节点的持久状态只保留小型引用和状态信息：

| 字段 | 含义 |
|---|---|
| videoEditProjectId | 编辑器工程存储使用的稳定 ID；节点首次打开时创建，之后复用 |
| videoEditInputRefs | 上游输入和用户导入素材的 artifact:// 引用列表 |
| videoEditOutputRef | 最近一次成功导出的 artifact:// 引用 |
| videoEditStatus | draft、exported、stale 或 failed |
| videoEditInputFingerprint | 生成当前导出时输入引用的稳定摘要，用于判断上游变化后旧导出是否过期 |

节点运行输出使用既有视频输出约定，把 **videoEditOutputRef** 投影为 **videoUrl/VideoArtifact**；工程 JSON 和媒体字节不放进节点数据。

状态规则：

- 第一次打开时创建工程，并把可用上游视频作为初始素材；若有多个上游视频，按画布输入顺序导入素材面板，由用户决定时间线摆放。
- 本地文件先通过 Artifact Service 导入；工程只保存返回的 artifact URI，不保留临时磁盘路径。
- 保存工程不代表完成节点；成功导出并成功写入 artifact 后更新输出引用及输入摘要。
- 上游引用发生变化时，把状态设为 **stale**，保留旧工程供恢复，但下游校验拒绝使用旧输出，直到重新打开并导出。
- 导出失败不更新 **videoEditOutputRef**；已有导出可保留并显式标 stale/failed。
- 删除节点不自动删除源视频、导出 artifact 或持久化工程；清理策略另走 artifact 生命周期管理，避免画布撤销/重做导致数据丢失。

### 4.3 现有 video-stitch

本方案不把 **video-stitch** 静默改成 **video-edit**，也不删除它。当前运行时未实现其执行器，实施后仍须在 UI/节点状态中如实呈现为未接通，不能作为本地编辑器的自动运行入口。

本轮明确不实现 **video-stitch** 的自动执行器；它继续显式显示为未接通，后续需作为独立功能另行设计确定性媒体执行器。交互式时间线编辑不能冒充无交互的 workflow **VideoCompose** 执行器。

## 5. 云端生成链路实施方案

### 5.1 供应商能力与请求参数

- 继续从画布视频场景配置解析供应商、模型和密钥；前端模型下拉不成为供应商能力的唯一事实来源。
- 将节点配置、路由结果、**CanvasVideoRequest** 和 provider request payload 做字段级对照，确保显示的选项确实传到网关。
- 将供应商差异放在现有 **CanvasModelGateway/provider adapter** seam 内，不在 UI 和 workflow runtime 散落供应商名称判断。
- **VideoGenerate** 保持可用。**VideoEdit**、**VideoExtend**、多帧输入和音频输入在没有 provider request/response 映射与回归测试前返回明确的 **UnsupportedCapability**。
- 分辨率、时长、比例、帧率等字段按供应商模型能力传递；模型不支持的选项应禁用或不显示。
- 供应商错误要保留 task ID、状态和可诊断错误分类；不得把失败任务渲染成成功视频。

### 5.2 任务状态、取消与恢复

- 保留已有任务 ID 续跑行为：再次运行时对同一个供应商任务继续轮询，避免意外重复提交产生额外费用。
- 点击停止后停止本地轮询，保留任务 ID；不要宣称远端生成任务已被取消，除非供应商确实提供并成功调用取消接口。
- 轮询等待应继续检查运行取消信号，并在终态、超时、网络失败、供应商失败时写入明确状态。
- 成功后先将视频保存为 artifact，再发送节点完成事件；失败下载或保存不得把临时 URL 写入节点。
- 生成视频下载改为流式落盘并计算长度/摘要，不先将整段 response 读入内存。

### 5.3 视频参数的交付顺序

1. 第一阶段对齐当前已实现的 prompt、模型、单图片参考和分辨率参数。
2. 核对每个已支持供应商对时长/画幅参数的真实字段和范围；逐模型接通并增加请求 payload 测试。
3. 只有模型 capability 信息能明确证明首尾帧、视频输入编辑或延长受支持时，才启用相应 operation 与控件。
4. 不用把多种模型强行映射到一个未经验证的通用 JSON 字段来制造表面兼容。

## 6. 本地编辑器与适配器

### 6.1 授权与技术验证门槛

正式集成 ArtCraft 之前必须完成：

- 取得涵盖本产品分发/商业使用的书面许可，并记录许可范围和版本。
- 在当前桌面端 Tauri WebView 验证 GPU/WASM 初始化、WebCodecs/MediaBunny 解码与编码、长视频内存行为及文件拖入。
- 确认上游视频 artifact 可作为编辑器媒体源打开，导出 Blob 可可靠写入统一 artifact 库。
- 比较依赖树、React 版本、构建产物和包许可证；优先在本项目采用有边界的 vendored/workspace integration，不假定 ArtCraft 的组件已作为可发布 npm 包。

授权未完成或运行验证失败时，停止集成步骤；云端视频生成继续独立可用，不回退或删除生成器。

### 6.2 适配器边界

沿用 ArtCraft VideoEditor 的适配器 seam，但实现 DeepAgent 自己的适配器：

| 适配器 | DeepAgent 行为 |
|---|---|
| projectStorage | 按 videoEditProjectId 保存/恢复工程；先验证 IndexedDB 在当前 WebView 的持久性，必要时使用应用数据目录持久化 |
| mediaSource | artifact:// 通过 Tauri artifact URL/文件读取接口解析；本地 File 经 Artifact Service 导入后返回可解码媒体引用 |
| exportSink | 接收 MP4/WebM 导出，流式写入 Artifact Service，成功后回传新 artifact URI 给编辑节点 |
| toast | 复用系统现有通知组件，不使用 ArtCraft app 自己的账号或云媒体上传逻辑 |
| authUser | 使用 DeepAgent 当前用户展示信息；无用户身份依赖时使用最小匿名展示实现 |
| assetGallery | 可从画布已有媒体库选择素材；首期至少支持节点上游视频和本地文件导入 |

禁止复用 ArtCraft 桌面宿主中上传到其云媒体 API 的媒体适配器，也禁止把其默认下载到浏览器的 export sink 当作 DeepAgent 的节点结果保存实现。

### 6.3 编辑器挂载与生命周期

- 从 **video-edit** 节点配置面板或节点操作打开全屏编辑界面；关闭只退出编辑界面，不删除工程和 artifact。
- **VideoEditor** 使用编辑器要求的实例初始化流程。切换节点时先保存当前工程，再按稳定工程 ID 加载目标工程；防止全局 EditorCore 单例继续显示上一节点工程。
- 导出回调必须写成明确的 DeepAgent adapter/事件，不通过临时覆盖方法、猴子补丁或依赖 render 闭包代理。
- 保存工程和导出视频是两种独立动作：自动保存负责恢复时间线，显式导出负责产生节点可下游消费的视频。
- 导出格式首期使用编辑器实际验证可用的 MP4/H.264 和 WebM/VP9；导出失败需要保留工程草稿并允许重试。

## 7. 大文件与 Artifact Service

### 7.1 现状限制

现有 **CanvasArtifactService** 对所有媒体统一设置 64 MiB 上限；现有导入接口包含 data URL 路径，视频编辑若直接将大型 **Blob** 转成 base64 或 **number[]**，会产生额外内存副本并可能耗尽 WebView 内存。

### 7.2 目标存储行为

- 继续使用既有 artifact 数据库索引和 artifact 根目录；不创建视频专用数据库或第二套媒体存储。
- 增加面向桌面本地视频的文件/流式导入和导出路径；限制在应用管理的临时目录和 artifact 根目录，拒绝任意目标路径写入。
- 写入先进入受管临时文件；边写入边计数、计算摘要，并收集 MIME sniff 所需的头部字节；完整成功后原子移动文件并提交数据库索引。
- 取消、断电模拟、格式无效、磁盘写入失败或索引提交失败时清理临时文件；不得出现有索引无文件或有最终文件无索引的半成品。
- 供应商下载也改用同一受管流式写入路径，成功任务超出旧上限时仍能被保存。
- 生产 UI 不暴露绝对路径；节点和工程只保存 artifact URI。
- 增加磁盘空间不足、写入权限不足和文件大小/时长超出设备能力时的清晰提示。内存/解码器能力限制由编辑器探测，不以无限制导入为承诺。

### 7.3 URI 和缓存

- 持久层统一保存 **artifact://<id>**。
- **convertFileSrc**、blob URL、provider signed URL 仅为当前渲染或编辑生命周期临时解析值；关闭编辑器后释放创建的 blob URL。
- 若当前 Artifact Service 预览接口无法高效提供大视频，扩展该服务的 Tauri 只读文件/范围读取边界；不在前端拼接本地绝对路径。

## 8. 数据迁移、运行时兼容与错误处理

### 8.1 旧画布兼容

- 不删除或重命名现有 **video-gen** 字段；继续读取旧 **videoModel**、**videoPrompt**、**videoInputUrl**、**videoUrl**、**videoTaskId**、**videoProgress** 和 prompt profile 字段。
- 不清理旧任务 ID；用户重跑旧的 running 节点时继续现有同任务续跑行为。
- 新版首次载入仅为新 **video-edit** 节点建立默认工程 ID/空输入状态，不批量重写旧节点。
- 旧的过期 **artifact://**、**data:** 或 HTTP 引用按现有兼容读取规则处理；只有经过明确迁移与用户确认才转换引用。
- 如果某个旧节点设置了后端不支持的 operation，应显示可诊断错误，不静默改成 **VideoGenerate**，以免重复付费。

### 8.2 编辑节点与上游变化

- 输入摘要只对稳定的 artifact URI 列表和顺序计算，不对临时路径或显示 URL 计算。
- 上游输入变化时标记 stale，编辑工程仍保留，用户可重新载入素材后继续。
- 工作流执行校验编辑节点：无输出、stale、输出 artifact 丢失或类型不是 Video 时失败并指出节点。
- 导出保存成功但前端关闭/崩溃时，工程和 artifact 保持可恢复；重新打开时通过已提交的 project state/output ref 恢复。

### 8.3 错误映射

| 错误场景 | 节点/界面行为 |
|---|---|
| 云端供应商未配置/密钥缺失 | 生成前失败，指向视频场景供应商配置 |
| 供应商 operation 不支持 | 返回 UnsupportedCapability 和模型信息，不发送请求 |
| 用户停止轮询 | 保留 task ID，节点状态显示已停止/可续跑；不谎报供应商已取消 |
| 供应商任务失败或超时 | 保留诊断信息和 task ID；不生成空视频输出 |
| artifact 下载/写入失败 | 任务不标记成功，临时数据清理，可在供应商链接仍有效时重试 |
| 编辑器/WASM 初始化失败 | 编辑界面显示可恢复错误，生成节点仍正常工作 |
| 本地导入/编解码不支持 | 不污染工程输入列表，提示格式/编解码器原因 |
| 导出失败/磁盘空间不足 | 保留自动保存工程和上次输出，不覆盖源视频 |
| 上游变化后使用旧导出 | 标记 stale 并阻止工作流消费旧结果 |

## 9. 分期实施

### Phase 0：实施前验证

- 审核 ArtCraft 当前许可证并取得书面授权，明确允许的集成、分发和修改范围。
- 用实际 Tauri WebView 加载编辑器，验证初始化、工程加载/保存、本地视频导入、artifact 视频打开、MP4/WebM 导出。
- 测量大文件导入、预览、导出时的峰值内存和 UI 响应。
- 检查当前 ArtifactStore 的索引事务、文件路径和清理接口，确定流式提交方案。
- 输出 go/no-go 结果。授权或技术验证不通过则停止编辑器集成；云端生成链路不受影响。

验收：上述验证均有可复现记录；供应商生成不会被修改或移除。

### Phase 1：云端生成能力对齐

- 对照 UI、节点序列化、**CanvasVideoRequest**、gateway 和 provider payload，列出真实支持字段。
- 修复无效参数控件；接通并测试供应商确实支持的时长/尺寸参数。
- 保持任务 ID 续跑、进度、取消、超时和供应商错误信息兼容。
- 将 provider 视频下载转换为 artifact 流式落盘，打通超过旧 64 MiB 上限的成功生成保存。
- 让节点合同和 UI 对未实现的编辑/延长操作表现一致。

验收：文生视频和已接通的图片参考生视频实际请求字段正确；完成后结果为 artifact URI；超大文件及取消/重试路径有回归测试。

### Phase 2：统一 Artifact 大文件接口

- 新增受管流式写入/读取入口，复用 artifact ID、DB 索引、MIME 和摘要字段。
- 将本地视频导入、编辑导出、云端生成下载接入同一受管路径。
- 加入原子提交、取消清理、索引一致性和范围/路径边界测试。
- 保持现有小文件 dataUrl 导入调用兼容；图片等已有用例不回归。

验收：视频读写不经 base64/number[] 完整副本；故障注入无临时文件或数据库孤儿记录。

### Phase 3：交互式本地编辑节点

- 新增 **video-edit** 节点定义、类型、配置面板、节点内容预览、操作入口和输出投影。
- 按稳定工程 ID 初始化或恢复 ArtCraft 项目，接入 DeepAgent ProjectStorage、MediaSource、ExportSink、Toast 和资产选择适配器。
- 输入视频来自上游 artifact 或用户选择的本地文件；后者先进入统一 artifact 库。
- 工程自动保存；显式导出写入新的 artifact 并更新编辑节点输出。
- 输入变化标 stale；工作流校验 stale/未导出/丢失资产状态。
- 处理编辑器单例切换、退出、错误边界、blob URL 释放和并发导出。

验收：编辑节点能在同一会话、切换会话及桌面重启后恢复工程；导出产物可预览并流向下游；原始视频保持不变。

### Phase 4：端到端回归与发布准备

- 对创意画布和专业画布验证节点注册、持久化、回放和输出引用。
- 验证旧 video-gen 画布升级前后可读取、可续跑、可重新生成。
- 完成 Tauri UI 手动验收、性能检查、许可证/依赖清单和用户说明。
- 确保 **video-stitch** 状态仍如实标注未实现；本轮不实现其自动拼接执行器。

## 11. 验证与验收

### 11.1 Rust 回归

- video-gen 文生视频请求包含已支持字段并选择正确模型/供应商。
- 图片参考生视频只接受 Image artifact；Video/Audio 输入不能误当首帧图。
- 不支持的 VideoEdit/VideoExtend 请求不会提交云端任务，也不会错误回退为生成。
- 中断后重跑继续同一 task ID；供应商任务失败、超时、无视频 URL 时状态和错误正确。
- 供应商返回大视频能流式保存；保存失败不能返回成功节点输出。
- artifact 流写入在取消、磁盘错误、索引错误后保持文件与索引一致。
- video-edit 只有在导出引用有效且输入摘要匹配时才返回 VideoArtifact。
- video-stitch 继续显式 Unsupported，除非其独立执行器已实现并测试。

### 11.2 桌面前端测试

- 已配置/未配置供应商时的模型选择与表单状态。
- 不支持的时长/分辨率选项不会让用户误以为请求已生效。
- video-edit 工程首次创建、自动保存、重启恢复、节点切换和 stale 转换。
- 本地文件导入成功/取消/损坏/不支持格式。
- 导出成功后将新 artifact:// URI 写回节点；失败不覆盖上次输出。
- 编辑器懒加载、退出清理、重复打开、全局编辑器单例和错误恢复。
- 大文件读写 IPC 不传输 number[] 或 base64；节点图不包含绝对路径或临时 URL。

### 11.3 手动端到端验收

1. 新建 video-gen 节点，选择云端模型并提交文生视频；看到任务进度并得到可播放 artifact。
2. 用一张画布图片运行图生视频；请求携带被选中的图片资产。
3. 停止轮询并重跑，确认沿用原 task ID；不产生第二次提交。
4. 把生成节点连到 video-edit，裁剪/调整时间线并导出；确认编辑节点展示新结果。
5. 重启桌面并重新打开编辑节点，确认时间线可恢复，导出仍可播放。
6. 导入本地视频和多个素材，验证大文件路径、导出失败提示和取消清理。
7. 修改上游视频后确认编辑节点标记 stale，下游运行被阻止，重新导出后恢复。
8. 确认旧画布的生成节点配置、已完成结果和待续跑 task ID 均仍可读取。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| ArtCraft 授权范围不覆盖本产品 | 不能合法集成或分发 | Phase 0 书面授权为硬门槛；门槛失败时停止编辑器集成，保持生成能力 |
| Tauri WebView 不支持目标媒体编解码器/GPU 路径 | 编辑/导出失败或降级 | 先做真实桌面 POC；运行时检测能力，失败提示，不损坏工程 |
| 视频文件过大占用内存/磁盘 | 桌面卡顿、进程退出、资产不完整 | 流式读写、临时文件、磁盘空间和解码能力检查、失败原子清理 |
| 编辑器单例跨节点状态污染 | 打开错误工程或覆盖其它节点草稿 | 按 stable project ID 显式保存/切换工程并测试快速切换和卸载 |
| 供应商接口参数差异 | 控件显示但请求不生效 | 显式 provider/model capability；每个已支持字段做 payload 测试 |
| 输入引用过期或上游变化 | 下游使用旧导出 | 以稳定 artifact URI 计算输入摘要，stale 时阻止执行 |
| 云端任务不可取消 | 用户以为供应商工作已停止 | 把本地停止轮询和远端取消状态区分显示；保留任务 ID |
| 大文件导出过程中应用关闭 | 临时数据残留 | 导出到受管 staging，事务提交后再发布 URI，启动时清理过期 staging |

## 13. 发布、迁移与回滚

### 13.1 发布顺序

- 先发布并验证 artifact 大文件 API；旧 dataUrl 小文件接口继续工作。
- 再发布云端生成字段对齐与流式下载；确认旧节点无需迁移。
- 最后在授权和桌面 POC 通过后启用 video-edit 节点。
- 可通过节点注册/功能开关隐藏编辑器入口；隐藏编辑器不影响已保存的生成视频或 artifact。

### 13.2 数据兼容

- 编辑节点字段采用新增、可选、默认缺省方式；旧画布 JSON 无需批量迁移。
- 新工程与编辑输出使用独立 ID/URI；删除节点不自动级联删除 artifact。
- 保留旧生成节点中的供应商任务 ID，以免破坏续跑。
- 任何历史字段清理或旧 artifact 清理都不属于本次迁移。

### 13.3 回滚

- 编辑器依赖或适配器出现问题时，关闭 video-edit 节点入口；保留节点 JSON、工程记录和 artifact，避免数据丢失。
- 回滚桌面前端不删除新 artifact；老版本仍可忽略未知编辑节点，恢复时不得覆盖用户数据。
- 云端生成改动可独立回滚；不得把编辑器回滚绑定为删除 MediaJob。
- 大文件写入格式保持原 artifact 文件与数据库索引契约；回滚不需要转换已有 artifact。
- 仅当确认某版本的 artifact 记录无法被旧服务识别时，才设计单独的数据库/文件迁移和恢复工具。

## 14. 完成标准

本方案实施完成需同时满足：

- 云端 video-gen 仍可通过配置的供应商生成视频，支持已验证的输入、参数、进度、停止和续跑。
- 生成结果与本地导入结果均存为稳定 artifact:// 引用，视频文件读写支持大于旧上限的流式路径。
- 独立 video-edit 节点可以恢复工程、编辑素材、导出新视频并向下游提供有效输出。
- 原始视频不会被编辑覆盖；编辑草稿、导出、stale、失败状态语义清楚。
- ArtCraft 只有在书面授权和 Tauri 兼容性门禁通过后才进入发行包。
- 旧画布可读取；没有实现的操作不显示为已支持。
- Rust 测试、桌面构建、授权/依赖检查和真实桌面手动验收均有记录。
